# 트라이팟 신호판

유튜브 채널 **송팀장**이 공개한 '트라이팟' 매매 규칙을 그대로 구현하고, 매 거래일 자동으로
판정해 대시보드에 표시하는 시스템입니다. 신호가 바뀐 날에만 이슈가 생성되고 메일이 옵니다.

- **대시보드** → `https://<사용자명>.github.io/<리포지토리명>/`
- **기계용 상태** → 같은 주소의 `state.json`
- 파이썬 표준 라이브러리만 씁니다. 설치할 패키지도, 발급할 토큰도 없습니다.

> 이 저장소는 규칙의 상태를 추적·표시할 뿐 투자 권유가 아닙니다.
> 레버리지 ETF는 원금 전액 손실이 가능합니다.

---

## 규칙

매 거래일 장이 끝나면 숫자 세 개를 봅니다. 셋이 각각 다른 것을 봐서, 다리 하나가 빠지면
삼각대가 넘어진다는 뜻으로 **트라이팟**입니다.

| | 보는 것 | 지표 |
|---|---|---|
| 다리 1 | 큰 방향 (추세가 살아 있는가) | 나스닥100 **250일 이동평균** |
| 다리 2 | 시장의 공포 | **VIX 10일 평균** |
| 다리 3 | 피로도 (고점에서 얼마나 멀어졌나) | **52주 고점 대비 낙폭** |

### 1단계 · 지금이 어떤 시장인가

| 조건 | 판정 |
|---|---|
| 지수 > 250일선 × 1.01 | 상승 |
| 지수 < 250일선 × 0.95 | 하락 |
| 그 사이 (−5% ~ +1%) | 직전 상태 유지 |

위아래 완충폭이 다른 건 선 근처에서 사고팔기를 반복하지 않기 위해서입니다.
"나갈 때는 신중하게, 들어올 때는 빠르게."

### 2단계 · 무엇을 살 것인가

| 시장 | 조건 | 배분 | 배수 |
|---|---|---|---|
| 상승 | VIX10 < 28 **그리고** 낙폭 9% 이내 | TQQQ 100% | 3.0× |
| 상승 | VIX10 ≥ 28 **또는** 낙폭 9% 초과 | QQQ 50% + QLD 50% | 1.5× |
| 하락 | VIX10 < 18 | QQQ 50% + QLD 50% | 1.5× |
| 하락 | VIX10 ≥ 18 | 현금 100% | 0× |

### 3단계

어제와 같으면 아무것도 하지 않습니다. 끝입니다.

**체결 가정** — 신호는 T일 종가로 확정하고 체결은 T+1 거래일입니다.
종가를 보고 그 종가에 사는 계산은 하지 않습니다. 이 하루 차이가 백테스트 수익률을
크게 바꿉니다.

## 검증

나스닥100 지수로 가상 QQQ·QLD·TQQQ를 합성(운용보수·조달금리·거래비용 반영)해
1991년부터 35년을 다시 돌린 결과입니다.

| 항목 | 영상 공개값 | 본 구현 |
|---|---|---|
| CAGR / MDD | 32.9% / −62% | 33.2% / −61.9% |
| 울서 지수 | 29.9 | **29.9** |
| 소르티노 | 1.08 | 1.17 |
| 연평균 매매횟수 | 8.1회 | 7.9회 |
| 매매 0회였던 해 / 최다 매매 연도 / 매매간격 중앙값 | 5년 / 21회 / 6일 | **5년 / 21회 / 6일** |
| QQQ 단순보유 CAGR / MDD | 15.4% / −82.8% | 15.3% / −82.8% |
| QLD 단순보유 CAGR / MDD | 19.7% / −99% | 19.6% / −98.8% |
| TQQQ 단순보유 CAGR / MDD | 16.4% / −100% | 16.3% / −100% |
| 10년 보유 원금손실확률 (QQQ/QLD/TQQQ) | 8.8 / 21.2 / 40.1% | 9.1 / 21.7 / 40.4% |
| QLD 대비 승률 (1/3/5/10년) | 59 / 62 / 76 / 78% | 59 / 62 / 76 / 80% |
| 전고점 회복 QQQ / QLD | 14.9 / 20.8년 | 15.0 / 20.8년 |

`python3 src/backtest.py` 와 `python3 src/validate.py` 로 언제든 재계산할 수 있습니다.

**알려진 차이 두 가지.**
영상은 '레버리지 축소'를 35년간 55회로 셉니다. 본 구현은 142회로 잡히는데,
총 매매횟수(연 7.9회 × 35년 ≒ 283회)는 영상과 같으므로 연속된 감속 구간을 하나로 묶어 센
다른 정의로 보입니다.
또 2026-07-28 낙폭이 −9.45%로 문턱을 살짝 넘겨 감속이 한 번 잡히는데, 영상(8월 말 촬영)에서는
"4개월째 무매매"라고 말합니다. 문턱을 몇 bp 차이로 넘나드는 날은 데이터 소스 하나 차이로
판정이 갈립니다.

## 설치

### 1. 리포지토리 만들기

GitHub에서 새 리포지토리를 만들고(**Public** 권장 — Actions 무제한·Pages 무료),
이 폴더의 파일 전부를 올립니다. 웹에서 **Add file → Upload files** 로 드래그해도 됩니다.

> `.github/` 폴더는 숨김 폴더라 드래그가 안 될 수 있습니다.
> 그럴 땐 **Add file → Create new file** 에 `.github/workflows/daily.yml` 을 경로째 입력하고
> 내용을 붙여넣으면 됩니다.

### 2. Pages 켜기

**Settings → Pages → Source: Deploy from a branch → Branch: `main` / `/docs` → Save**

1~2분 뒤 `https://<사용자명>.github.io/<리포지토리명>/` 이 열립니다.

### 3. 첫 실행

**Actions 탭 → 트라이팟 일일 신호 → Run workflow**

초록불이 뜨면 끝입니다. 이후로는 평일 한국시간 아침 8시에 저절로 돕니다.

### 4. 휴대폰에 얹기

모바일 크롬/사파리로 대시보드를 열고 **홈 화면에 추가**. 삼각대 아이콘이 붙고
주소창 없이 앱처럼 뜹니다.

## 운영

### 알림

신호가 **바뀐 날에만** 이슈가 자동 생성됩니다. 본인 리포지토리는 기본으로 구독 상태라
GitHub이 메일을 보냅니다. 안 온다면 **Settings → Notifications → Email** 이 켜져 있는지,
리포지토리 우상단 **Watch** 가 *All Activity* 또는 *Issues* 를 포함하는지 확인하세요.

워크플로가 **실패**하면 GitHub이 따로 메일을 보냅니다. 이건 기본 동작이라 설정할 게 없습니다.

### 조용한 고장 막기

세 겹으로 막아 뒀습니다.

1. **소스 교차검증** — 나스닥100은 Yahoo(query1/query2)와 FRED에서 받아 서로 대조합니다.
   0.5% 넘게 벌어지면 데이터를 쓰지 않고 워크플로가 실패합니다. 틀린 값을 조용히 남기느니
   실패해서 메일이 오는 편이 낫습니다.
2. **재검증** — FRED는 미국 동부시간 밤늦게 갱신돼 실행 시점엔 하루 뒤처져 있습니다.
   그래서 다음 실행 때 최근 6일치를 다시 대조합니다. 체결이 T+1이므로 이 재검증은
   그 값으로 실제 매매하기 전에 끝납니다.
3. **정지 배너** — 마지막 실행이 3일을 넘기면 대시보드 맨 위에 빨간 경고가 뜹니다.
   자동화가 멎었는데 옛날 숫자를 보고 있는 상황을 막습니다.

### 60일 자동중지

GitHub은 **리포지토리에 60일간 활동이 없으면 스케줄 워크플로를 자동으로 끕니다.**
이 리포는 매일 커밋이 쌓이지만, 봇이 만든 커밋이 '활동'으로 인정되는지는 공식 문서에
명확히 적혀 있지 않습니다. 대비책:

- 꺼지기 전에 GitHub이 **메일로 알려 주고**, Actions 탭에서 **버튼 한 번**으로 다시 켤 수 있습니다.
- 가끔 **Run workflow** 를 수동으로 눌러 두면 확실한 활동으로 잡힙니다.
- 대시보드의 정지 배너가 어차피 잡아 줍니다.

### 자가진단

`python3 src/selftest.py` — 네트워크 없이 30가지를 검사합니다.

- 과거 시세 구간(1989-12 ~ 2026-09-04)의 행수·바이트·체크섬
- 파서가 실제 응답 샘플을 제대로 읽는지, 소스 불일치를 잡아내는지
- 35년 백테스트 골든값(CAGR·MDD·울서·소르티노·매매횟수)이 그대로 나오는지
- 닷컴·금융위기·코로나 등 알려진 날짜의 규칙 판정이 같은지

**매 실행마다 CI에서 돌기 때문에**, 코드나 데이터가 조용히 어긋나는 순간 워크플로가 실패합니다.
다른 계정·다른 PC로 옮긴 뒤에도 이거 하나만 통과하면 같은 시스템이라는 게 증명됩니다.

## 튜닝

`config.json` 의 `active_preset` 을 바꾸면 됩니다.

| 프리셋 | 성격 |
|---|---|
| `original` | 영상 공개값 그대로 (기본) |
| `mild` | 순한맛 — 최대 배수를 2배로, 문턱을 앞당김 |
| `spicy` | 매운맛 — VIX 문턱 34, 낙폭 문턱 12% |

새 프리셋을 추가해도 됩니다. `python3 src/backtest.py <프리셋명>` 으로 즉시 재계산됩니다.

> 영상에서도 "VIX 28은 최적값이 아니라 내가 감당하기로 정한 위험의 크기"라고 밝힙니다.
> 문턱을 올리면 수익률과 낙폭이 **함께** 커집니다.

프리셋을 바꾸면 골든값이 달라지므로 `src/selftest.py` 의 백테스트 기대값도 같이 고쳐야 합니다.
(그래서 프리셋 변경은 의도적으로 번거롭게 만들어 뒀습니다.)

## 구조

```
config.json              파라미터 — 여기만 바꾸면 됩니다
data/market.csv          나스닥100·VIX 일간 종가 (1989-12 ~ )
src/engine.py            지표 계산 · 시장상태 판정 · 목표배분
src/fetch.py             시세 수집 (교차검증·이상치 거부·재검증)
src/report.py            오늘의 상태를 JSON 으로
src/build_site.py        docs/ 아래 정적 사이트 생성
src/template.html        대시보드 템플릿
src/backtest.py          35년 백테스트
src/validate.py          영상 공개 수치와 1:1 대조
src/selftest.py          자가진단 (네트워크 불필요)
src/make_icons.py        홈 화면 아이콘 생성 (한 번만)
docs/                    GitHub Pages 로 서빙되는 결과물
.github/workflows/daily.yml   매일 도는 워크플로
```
